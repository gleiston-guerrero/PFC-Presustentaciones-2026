# HU-06: Generación de actas de pre-sustentación (RF-06)

**Prioridad MoSCoW:** Must

## Formato Connextra
> Como **presidente del tribunal**,
> quiero **generar el acta final de pre-sustentación en PDF una vez concluida la evaluación**,
> para **dejar constancia formal del resultado obtenido por el estudiante**.

## Checklist INVEST

| Criterio | Cumple | Nota |
|---|---|---|
| Independent | ✅ | Depende de que la evaluación (HU-05) esté completa |
| Negotiable | ✅ | El formato exacto del PDF es negociable |
| Valuable | ✅ | Sin acta no hay validez académica del resultado |
| Estimable | ✅ | Alcance acotado |
| Small | ✅ | Una sola operación de generación |
| Testable | 🟡 | Verificable, pero sin prueba automatizada real hoy |

## Criterios de aceptación (Gherkin)

```gherkin
Feature: Generación de actas
  Scenario: Generación exitosa
    Given una solicitud con todas las evaluaciones de jurado completas
    When el presidente del tribunal envía POST /api/v1/actas/generar
    Then el sistema genera un PDF con los resultados consolidados
    And el acta queda en estado "Generada, pendiente de firma"

  Scenario: Intento de generar acta sin evaluaciones completas
    Given una solicitud con evaluaciones pendientes
    When se intenta generar el acta
    Then el sistema rechaza la operación
```

## Trazabilidad

- **Módulo backend:** Actas (`MinutesController`, `MinutesServiceImpl`, generación de PDF con iText)
- **Endpoint:** `POST /api/v1/actas/generar`
- **Prueba automatizada real:** ✅ **Resuelto parcialmente (2026-08-29).** El hallazgo original era real:
  `MinutesServiceImplTest.java` citado en `matriz.csv` v0.9.0-rc no existía. Se agregó la clase real, que
  cubre el **Scenario "Generación exitosa"** (solicitud existente → PDF real generado con iText,
  verificado en disco) y el caso de acta ya existente (idempotencia).
- **⚠️ Discrepancia real detectada entre este documento y el código (2026-08-29):** el **Scenario
  "Intento de generar acta sin evaluaciones completas"** describe un rechazo que
  `MinutesServiceImpl.generarActa()` **no implementa** — el método genera el PDF de todas formas cuando no
  hay evaluación registrada, mostrando "Evaluación pendiente de registro" como placeholder en el
  documento, en vez de lanzar una excepción. No se agregó esa validación al código de producción en esta
  ronda (cambiar el comportamiento de negocio no estaba en el alcance de esta auditoría de
  documentación/tests) y tampoco se reescribió este Gherkin para ocultar la discrepancia. Queda declarado
  como brecha abierta: o se implementa el rechazo, o se corrige este escenario para reflejar el
  comportamiento real intencional.
