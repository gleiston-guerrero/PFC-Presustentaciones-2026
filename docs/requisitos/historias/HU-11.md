# HU-11: Gestión de usuarios (RF-11)

**Prioridad MoSCoW:** Must

## Formato Connextra
> Como **administrador del sistema**,
> quiero **listar, crear, activar/desactivar y cambiar el rol de los usuarios**,
> para **mantener el control de acceso del sistema actualizado y seguro**.

## Checklist INVEST

| Criterio | Cumple | Nota |
|---|---|---|
| Independent | ✅ | Depende solo de autenticación (HU-01) |
| Negotiable | ✅ | Los roles exactos son negociables |
| Valuable | ✅ | Sin gestión de usuarios, el control de acceso no se puede mantener |
| Estimable | ✅ | CRUD + cambio de rol |
| Small | 🟡 | 31 controladores REST en total dependen indirectamente de que los roles estén bien gestionados aquí — el alcance de esta HU específica sigue siendo pequeño (gestión del catálogo de usuarios) |
| Testable | ✅ | Cubierto por prueba automatizada real |

## Criterios de aceptación (Gherkin)

```gherkin
Feature: Gestión de usuarios
  Scenario: Listado paginado (solo ADMIN)
    Given un administrador autenticado
    When envía GET /api/v1/usuarios/paginado
    Then el sistema responde con la lista paginada de usuarios

  Scenario: Acceso denegado a no-administradores
    Given un usuario autenticado con rol distinto de ADMIN
    When intenta acceder a GET /api/v1/usuarios
    Then el sistema responde 403 Forbidden

  Scenario: Cambio de rol
    Given un administrador autenticado
    When envía una solicitud de cambio de rol para un usuario existente
    Then el sistema actualiza el rol y lo refleja en futuros tokens JWT del usuario
```
