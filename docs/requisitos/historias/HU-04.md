# HU-04: Programación de cronograma de defensa (RF-04)

**Prioridad MoSCoW:** Must

## Formato Connextra
> Como **coordinador de carrera**,
> quiero **programar la fecha, sala y bloque horario de la pre-sustentación, verificando disponibilidad**,
> para **evitar choques de horario o de sala entre defensas distintas**.

## Checklist INVEST

| Criterio | Cumple | Nota |
|---|---|---|
| Independent | ✅ | Depende de que exista el tribunal (HU-03) y una sala registrada (HU-10) |
| Negotiable | ✅ | El algoritmo de verificación de disponibilidad es negociable |
| Valuable | ✅ | Sin cronograma no hay defensa posible |
| Estimable | ✅ | Alcance acotado |
| Small | 🟡 | El controlador expone 4 endpoints relacionados (crear, auto-asignar, verificar disponibilidad, listar) — un poco más grande que una HU mínima, pero cohesivo |
| Testable | 🟡 | Verificable, pero sin prueba automatizada real hoy |

## Criterios de aceptación (Gherkin)

```gherkin
Feature: Programación de cronograma
  Scenario: Programación exitosa sin conflicto
    Given una sala disponible en el bloque horario solicitado
    When el coordinador envía POST /api/v1/cronogramas/crear con sala, fecha y bloque
    Then el sistema crea el cronograma en estado "Programado"

  Scenario: Conflicto de disponibilidad
    Given una sala ya reservada en ese bloque horario
    When el coordinador intenta programar otra defensa en la misma sala y bloque
    Then el sistema rechaza la operación e informa el conflicto
```
